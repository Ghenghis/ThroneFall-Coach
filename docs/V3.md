# v3 Roadmap — what the bot still can't do

Generated from the subagent coverage audit + `proposals.jsonl` (MiniMax's engineering queue) +
run-history analysis. Plugin version is already `3.0.0`; this file is the release checklist.

## Action vocabulary

`ActivateShrine`, `CastAbility`/`SwapWeapon`, `BuyItem`, `Repair`, `OpenLoadout`.
New snapshot fields: `AbilityReady`, `Castles[]`, `DamagedBuilds`, `ObjectiveType`, `ShrineCost`.

## Blockers for the remaining campaign (priority order)

1. ~~**Building-loss tracking**~~ SHIPPED — `blost` tracks `Hp.KnockedOut`, decrements `CatBuilt`, restores on
   dawn revive, drops marker on repair `BuildDone`.
2. **Multi-keep / objective awareness** — `CastlePos` is a single nearest keep; escort/timed/boss variants have no
   `ObjectiveType` and would be played as plain castle defense. `BLOCKER` for Moorweg/Totend/Wildbach class maps.
3. ~~**Boss/elite posture**~~ — SHIPPED (`elite_stall_hp`: stall, don't duel, when an elite is on him and
   troops exist).
4. ~~**Post-death recovery**~~ — SHIPPED (`revived-reset`: re-arm door posts, restart army phase on respawn).
5. ~~**Shrine activation**~~ — SHIPPED v1: shrine visit leg (army≥70% target, no threats) walks the commanded blob
   to the shrine and PlaceArmy's inside `collectionRange` (shrines charge on deaths — `Shrine.DeathOfUnitAt`).
6. **Real in-match perk picks** — `PerkSelectionItem` branch is dormant (bypassed); in-run perk frames get
   auto-closed, not chosen. HIGH — run-shaping choices are being skipped.
7. **Quest-aware level scoring + cross-session defeat memory** — `LevelScore` ignores quests/crowns; session-only
   `sessionDefeats`.
8. ~~**Call-night precondition**~~ — SHIPPED: `PlayerInteraction.IsFreeToCallNight` gate before `SwitchNight`,
   `night-blocked` note when refused.
9. **Mid-match weapon/ability intents** — Lightning Wand AoE etc. never invoked; challenge botpacks need it.
10. **Shop/merchant frames** (Blacksmith/Royal Forge) — unrecognized frame type → auto-close; needs a live frame dump
    to confirm names. Also doubles as the late-game gold sink (gold hoarding at victory is a known waste —
    postmortem just caught it: "5107 unused gold at end").

## Orchestration / coaching (all shipped)

- MiniMax heartbeat + engineering digest + proposal channel + outcome feedback (closed loop, cause→effect visible).
- Command center: OFF/SEMI/AUTO/AGGRO modes, 15 s–3 h scheduler, approval queue, outcome card.
- Postmortem loop: MiniMax autopsies every finished run (`kind:postmortem` in mmwatch).
- Map-intel generator: auto playbooks for all 37 scenes + `LoadStrategy` fallback.
- Pin awareness: `pin-type` classifies the blocking collider (pen/gate/wall/terrain/enemy).
- Stuck→GPS escalation: pins on "reachable" goals feed `NoteNavFail`.
- Upgrade urgency: built+upgradeable slots no longer starve under the playbook pin.
- Writer arbitration: user-cmd pins overrides 240 s; advisory replies are comment-only while pinned.

## QA / verification gaps (v3 must include)

- Replay fixtures per level (only `durststein-dto` exists): Frostsee victory run, a defeat path, a HeroDead run,
  a choice-wedge run, a gate-cross leg.
- `BotBrain.Decide` branch unit tests: night gate, door-park escalation, visit-abandon, policy `Parse`.
- GatePlanner fuzz on nav-area renumbering (the real failure mode).
- `verify.ps1` end-to-end assertions on `summary.json` (result == victory, useful_pct floor, waves reached).

## Telemetry gaps (needed so MiniMax can see these)

- Intent-effect events: `PlaceSquad` → did `DoorUnitAt` actually rise 5 s later? (root of "posted but never arrived")
- Wall-loss/building-destroyed events.
- `objective_type`, `near_enemy_elite`, `next_wave_max_hp` in the MiniMax digest fields.
- `door_units` metric fix (fires but reads 0 — perception bug).
