# 03 - Combat, Units and Targeting (Thronefall, decompiled C#)

**Conventions.** `File.cs:line` = `Trainer\decompiled\`. *asset* = value serialized in prefabs/ScriptableObjects (section g). `(def X)` = C# field initializer; an asset may override it. dt = Time.deltaTime. Day = build phase, Night = combat. Lowercase words in backticks inside formulas (`rand`, `lerp`, `clamp01`, `edge`, `pct`, `rate`, `mods`, `dist`, `ticks`, `def`, `attackerMult`) are pseudo-code, not C# names. Asset values quoted as *asset* were read from `reference\data\` (see Verification log at the end).

## (a) Facts from code

**Tags and registries**
- `ETag` has 51 values (0-50, `NONE`=39); each TaggedObject keeps a 64-bit mask (TagManager.cs:7-60; TaggedObject.cs:14,98-130).
- `PlayerUnits`/`EnemyUnits`/`Players` are filled from an object's *initial* tags at enable; runtime `AddTag` does not update them (TagManager.cs:141-145,157-175,193-200). Other registries: `playerBuildingInteractors` (BuildingInteractor.cs:178), `coins`, `freeCoins` (Coin.cs:67-74), `freeEnergyCores`, `energyCores` (TagManager.cs:131-139).
- Query = has ALL `mustHave`, NONE of `mayNotHave`; empty `mustHave` returns nothing (TagManager.cs:216-266).
- Distance is 3-D (altitude counts), from the attacker's `transform.position` (not the projectile origin) to the target position, or to `colliderForBigOjectsToMeasureDistance.ClosestPoint` if set (TagManager.cs:416-423; AutoAttack.cs:125-133).
- Tags with code effects: `AUTO_Alive` (Hp.cs:217-220,404); `AUTO_KnockedOutAndHealOnDawn` (Hp.cs:319,405); `AUTO_NoReviveNextMorning` (Hp.cs:484-491); `AUTO_Commanded` (CommandUnits.cs:578,607); `Flying` (AimbotProjectile.cs:94; CommandUnits.cs:226); `FastMoving` (Weapon.cs:262); `RangedFighter` (Weapon.cs:253); `MeeleFighter` (PathfindMovementEnemy.cs:147); `Player` (Weapon.cs:251; PathfindMovementEnemy.cs:103); `PlayerShrine` (Shrine.cs:136); `PlayerHeroUnit` (CommandUnits.cs:180); `VodooCursed` (CurseBlastMA.cs:43); `PlayerOwned`, `Building` (Hp.cs:232,512,521); `EnemyOwned` (night-end count EnemySpawner.cs:391,417; BarricadeDamage.cs:49; RidingDamager.cs:85); `PlayerUnit` (CommandUnits.cs:169,178,189,200; AutoRevive.cs:117). Tags read in C# only by perks, waves, UI, spawning, day/night flow, the stall tie-breaker or army groups, not by per-hit combat rules: `Tower`, `Wall`, `WallOrTower`, `House`, `Bridge`, `CastleCenter` (also DayNightCycle.cs:116, PlayerInteraction.cs:81), `Boss` (TieBreaker.cs:80), `Monster`, `SiegeWeapon`, `NaturallyVulnerableToSplash` (SuperWaveGen.cs:1374,1386), `LargeUnit`, `Humanoid`, `Exploding`, `OnDeathEnemySpawner`, `PracticeTargets`, `Group1-3`. Several of them still steer combat through asset target/damage lists (`SiegeWeapon`, `Monster`, `Boss`, `Wall`, `Tower`, `CastleCenter`: balance_sheet.json). Tags with no code reference, hence meaningful only via asset tag lists: `Healer`, `InfrastructureEconomy`, `TakesReducedDamageFromPlayerAttacks`, `ArmoredAgainstRanged`, `VulnerableVsRanged`, `TakesIncreasedDamageFromTowers`, `PlayerOwnedPriorityTarget`, `BlockableEnemyProjectile`, `UselessWallThatDoesNotBlockPath`, `MagicProjectile`, `NaturallyHighHealthTarget`, `UnreachableForBigEnemiesDueToLevelDesign`, `FireAndExplosionResistant`, `TrainingFacility`, `Undead`, `Vampire` (grep of all decompiled classes; enum at TagManager.cs:7-60).

**Hp**
- `KnockedOut = hp<=0`, `Alive = hp>=0` (Hp.cs:126,158). No armor stat exists; only `HpWithDamageReduction` scales damage by `1-clamp01(rate)` (HpWithDamageReduction.cs:7-14), switched by hold-position for shield bearers (PathfindMovementPlayerunitShieldBearer.cs:19-25).
- Knockout vs destroy is per prefab (`getsKnockedOutInsteadOfDying`, Hp.cs:13,402-412; bosses flip it: LavaGolemPhasing.cs:247, CrystalDragonPhasing.cs:345). Knockout disables AutoAttack, ManualAttack, movement, RVO, NavmeshCut, PlayerInteraction and sets `PlayerMovement.Dead` (Hp.cs:252-308).
- `Revive(pct)`: if hp<=0 re-enable all and hp=`maxHp*pct`, else `hp+=maxHp*pct` capped at maxHp (a full heal only for the default pct 1) (Hp.cs:310-338). `Heal` ignores hp<=0 and multiplies by `healingMultiplyer` (Healing Spirits, PlayerOwned; Hp.cs:232-235,436-447).
- Dawn (after `sunriseTime`: def 2.5 s, asset 3.0 s in all 37 level scenes) revives and fully heals every PlayerOwned object without `AUTO_NoReviveNextMorning`, then makes it invulnerable; dusk clears invulnerability (Hp.cs:506-535; DayNightCycle.cs:28,144,224,286-292). Destruction God alternates building revival and revives buildings at `destructionGodHealthRegen` (Hp.cs:518-534).
- Building max HP = prefab `Hp.maxHp` (asset, e.g. Wall 240, Tower 100, Castle 100) + sum of upgrade `hpChange`; an upgrade to level>1 of a knocked-out building revives it at 1 HP + `hpChange` (BuildSlot.cs:907-919; tooltip sum: BuildSlot.cs:474,485).
- Night ends when spawning is done and no EnemyOwned remain (DayNightCycle.cs:112-115). Defeat when any `objectsThatTriggerLoseWhenDestroyed` Hp is killed/knocked out (LocalGamestate.cs:33,83-89,159-165).
- Healthbar is display-only: hidden at exactly 100% HP (Healthbar.cs:156-164).

**Day gating.** Default AutoAttack, Tower, MinRange, Delay, LowestInRangeMulti, TrapTower, Flamethrower do not tick in Day (AutoAttack.cs:89-92; AutoAttackTower.cs:27-30; AutoAttackWithMinRange.cs:10; AutoAttackWithDelay.cs:15; AutoAttackLowestInRangeMulti.cs:28; AutoAttackTrapTower.cs:45; AutoAttackFlamethrower.cs:170); Adaptive-weapon and TwoTargets have no Day check (AutoAttackPlayerUnitAdaptiveWeapons.cs:29-35; AutoAttackTwoTargets.cs:7-9). Hero manual attack is refused in Day; the passive (`autoAttack`) one is not (ManualAttack.cs:205).

**Perk modifiers** run once at Start, then destroy themselves: HP `maxHp*=hpMultiplyer` (+ scales building `hpChange`, heals) (PerkHpModifyer.cs:39-73); speed `movementSpeed*=` (PerkSpeedModifyer.cs:12-19); range multiplies every AutoAttack priority `range` and movement `keepDistanceOf` (PerkRangeModifyer.cs:16-30); cooldown multiplies `cooldownDuration` and `recheckTargetInterval` (PerkCooldownModifyer.cs:12-20); weapon swap (PerkWeaponModifyer.cs:11-18); child AutoAttack damage `*=` (PerkDamageAutoAttackModifyer.cs:11-22); Archery Skills projectile speed and Warrior/Commander ally damage on AutoAttack, HotOilTower, BarricadeDamage (PerkDamageModifyerPlayerunitAuto.cs:5-53); Indestructible strips `PlayerOwned` (PerkIndestructible.cs:11-17).

## (b) Inferences (not proven by code alone)
- I1. Hero, player units and buildings have `getsKnockedOutInsteadOfDying=true` in prefabs: AutoRevive, UnitRespawnerForBuildings and BuildingInteractor all rely on knockout (AutoRevive.cs:97; UnitRespawnerForBuildings.cs:113; BuildingInteractor.cs:170). Ordinary enemies are destroyed.
- I2. The passive hero weapon needs `attackMarkerPosition` assigned in its prefab, else it never buffers an attack (ManualAttack.cs:143-158).
- I3. Enemy *AutoAttack* lists may still hit `AUTO_Commanded` units; only enemy *movement* lists veto them (PathfindMovementEnemy.cs:136-139).
- I4. `ExplosionWeapon` falloff `1-(edge-center)*d²/R²` looks inverted (edge<center gives >1 at the rim; the multiplier is always 1 at the centre, so only edge-center matters) (ExplosionWeapon.cs:25-31).
- I5. `speedBoostDuringDaytime` is dead code (PathfindMovementPlayerunit.cs:23). `maximumDistanceFromHome` is not enforced outside hold mode, except by healers (TargetPriority.cs:315-320; PathfindMovementPlayerunitHealer.cs:38).
- I6. RVO `priority` semantics (PathfindMovementPlayerunit.cs:396; PathfindMovementEnemy.cs:310) live in the A* library, absent from this folder; same for NavmeshCut: disabled cuts (Hp.cs:295-299) presumably reopen paths when walls/buildings fall.
- I7. Shrine XP comes only from spawned enemies: `HpOriginal` is set only in Spawn.cs:225,381.
- I8. Who attacks whom is data-driven (tag lists); the extractor must supply the lists.
- Open questions: real ranges/speeds/cooldowns/damage tables (assets); which Hp objects sit in `objectsThatTriggerLoseWhenDestroyed`; whether the hero has a distance collider; RVO priority semantics; `attackMarkerPosition` on passive weapons; per-prefab knockout flags. Answered or narrowed from asset data in the Verification log (end of file).

## (c) Damage pipeline (weapon -> shrine XP)

**1. Trigger.** AutoAttack: `cooldown-=dt`; at <=0 find target; none -> `cooldown+=recheckTargetInterval` (def 0.5, so acquisition can lag that long); found -> `cooldown+=cooldownDuration*(1+(1-2*rand)*cooldownRandomization)` and attack; start value `cooldownAfterSpawn` (def -1) (AutoAttack.cs:83,93-108). Hero: section f.

**2. Weapon.Attack** (Weapon.cs:92-153). Aim = target collider closest point, or position + `hitFeedbackHeight` up; `performRaycastBeforeShooting` retargets to the first Hp hit (Weapon.cs:96-112). If `projectileSpeed>0` and a projectile prefab exists -> homing projectile, damage deferred (Weapon.cs:113-139). Else instant: spawn FX whose `SplashDamageArea`s hit each distinct Hp in a sphere/box on `layerMaskRecieveDamage`, once per spawned FX, then direct damage (Weapon.cs:140-152,155-197; SplashDamageArea.cs:38-50). `splashDamage` is never used on the projectile path.

**3. Projectile.** Speed = `projectileSpeed*projectileSpeedMultiplyer` (AimbotProjectile.cs:112). Each frame it re-aims at the target's current point (AimbotProjectile.cs:118-128) and advances linearly; the arc only offsets the visual (AimbotProjectile.cs:146-158). Hit when `speed*dt >= distance left` (AimbotProjectile.cs:129-131): if the target object still exists -> `Weapon.DealDamage` (AimbotProjectile.cs:135-138); then the ground prefab (air prefab if the target was `Flying`) spawns with `WeaponDamageDealer.DamageMultiplyer = finalDamageMultiplyer*BlacksmithMulti` (AimbotProjectile.cs:139,197-216). Target destroyed in flight -> no direct damage, impact prefab still spawns; target merely knocked out -> no-op (Hp.cs:359-362); no shot reservation, so overkill shots are wasted. Chase limit `maximumChaseRange` (def 10000; Weapon.cs:47; AimbotProjectile.cs:106,168-172); once used up the projectile stops tracking and deals no direct damage on arrival (AimbotProjectile.cs:135,168-172); ranged enemy weapons have finite limits (weapons.json `maxChaseRange`: E Archer 22, E Crossbow 22, E Flyer 12, E Enemy Tower 35), player-unit damage weapons 10000, healing weapons 40. Nothing physical blocks it; only `AimbotProjectileExt` (Blockable) dies on crossing a `ProjectileBlock` sphere (AimbotProjectileExt.cs:11-28; ProjectileBlock.cs:34-44) and `BlockProjectiles` domes delete the nearest tagged projectile every `blockInterval` (BlockProjectiles.cs:41-59).

**4. Weapon.DealDamage** (Weapon.cs:199-273; DamageModifyer.cs:13-14,28-41):
```
F   = attackerMult * B
B   = meleeDamage | rangedDamage | 1/meleeResistance | 1/rangedResistance | 1     (Weapon.blacksmithEffect)
acc = 0; for m in list order: if target.Tags ⊇ m.requiredTags: acc = (acc + m.damageAdded) * m.damageMultiplyer   (def add 0, mult 1)
D   = acc * F      (list = splashDamage for area hits, else directDamage)
```
`attackerMult`: `AutoAttack.damageMultiplyer` (AutoAttack.cs:117); hero `PlayerDamageMultiplyer` (ManualAttack.cs:258). A weapon only hurts tags matched by its modifier lists; no match -> D=0 -> nothing. Then `Hp.TakeDamage(D, attacker, isPlayerWeapon)`; D==0 stops here; else `additionalWeaponEffects` run; Magic Armor: if the target has `Player` and lost HP, the attacker takes flat `damageVersusRanged` (attacker `RangedFighter`) or `damageVersusMelee` (Weapon.cs:243-261); then `Slow(slowsFastEnemiesFor)` on `FastMoving` targets (Weapon.cs:262-272).

**5. Hp.TakeDamage(D)** (Hp.cs:357-434): return if hp<=0 or invulnerable; D<=0 -> `Heal(-D)` (healing weapons use negative damage); enemy movement gets aggro from the attacker; `hp-=D`; events; hp<=0 -> step 6. `HpWithDamageReduction` scales D first.

**6. Death sequence** (Hp.cs:383-431), in order: OnKillOrKnockout events -> FX -> `enemyToSpawnOnDeath` -> knockout (tag swap, components off) or destroy (+shrine XP) -> coins -> `spwanAttackOnDeath.Attack(pos, ..., Hp.damageMultiplyer)`. `TakeDamage` returns true only for the killing hit (`targetKilled`).

**7. Coins** (Hp.cs:413-426). `coinCount` coins: #0 at `pos+up*coinSpawnOffset`, #i>=1 two units out at angle 45°*i. They fly to the hero once within `coinMagnetRadius` (def 10, asset 7 in all 36 hero scenes) after `spawnAnimationDuration` (def 1 s) at `maxSpeed` 20; pickup within 0.1 of hero+2 up (PlayerInteraction.cs:11,250-261; Coin.cs:7,13,31,33,90-121). At dawn all `freeCoins` fly to the hero (DayNightCycle.cs:170-175). A spawn's `goldCoins` are randomly split across its enemies (Spawn.cs:90-101,159-162).

**8. Shrine XP** (Shrine.cs:163-181). Only on *destroy*: every `PlayerShrine` within `collectionRange` (def 10, asset 20 in all 121 shrines) of the death gains `HpOriginal` = enemy base `maxHp` before scaling (Spawn.cs:225,381). At `currentXp>=maxXp` (def 1000, asset 350 in all 121 shrines): gold income `+incomeOnceUnlocked` (def 2); for each already-active shrine, both that shrine and the newly activated one get AutoAttack damage `*strengthBonusOnAdditionalShrine` (def 1.2) (Shrine.cs:24-36,87-161,214-221).

**9. Enemy scaling at spawn** (Spawn.cs:85-86,164-265):
```
HP  = baseMaxHp * difficultyMulti * (elite?4) * turtle * warGodsHp * antiAirHp(Flying) * growthHp * rangeGodHp(ranged, non-flying)
DMG = tableDamage * lerp(1,difficultyMulti,0.5) * (elite?3) * tiger * warGodsDmg * antiAirDmg * growthDmg * rangeGodDmg      (AutoAttack.DamageMultiplyer)
growth = growthGodMax^(wave/max(1,waves-1))
```
turtle/tiger/falcon = Taunt perks (PerkManager.cs:63-76); antiAir/warGods/growth/rangeGod: PerkManager.cs:185-188,211-214,252-272. Falcon scales enemy speed and player-agro time; Range God also scales attack cooldown, move speed, range and keepDistance (Spawn.cs:231-265). The wave UI shows +X% HP and +X/2% damage (PauseUILoadoutHelper.cs:197-199).

**10. Player-side multipliers.** Blacksmith research multiplies by `multiplyer` after `researchTime` dawns, only if the smithy was not knocked out that night (BlacksmithUpgrade.cs:41-63,69-86); perks and Empire (gold-scaled at dusk) also feed `BlacksmithUpgrades` (BlacksmithUpgrades.cs:22-40; EmpireUpgrade.cs:42-56). Invulnerability: Day, hero shield MA, `ShieldOnFirstDamaged` (full heal + invulnerable `shieldDuration`, once per night, re-armed at dawn: ShieldOnFirstDamaged.cs:21-42,51-63,70-73). RoyalProtection scales HP of commanded units (CommandUnits.cs:579-582). Health Potions heal PlayerUnits every 2 s (GlobalHealing.cs:39-43,52-63).

**11. Non-Weapon damage.** `ExplosionWeapon`: each target in `targetPriority.range` takes `DamageModifyer.CalculateDamageOnTarget(target, mods, 1-(edge-center)*d²/R²)`; no attacker, no attacker multiplier (ExplosionWeapon.cs:18-33). `FireArcherBurn`/`HotOilTower` apply `total/ticks` per tick with no attacker, hence no aggro (FireArcherBurn.cs:75-88; HotOilTower.cs:87-105); `BarricadeDamage` slows then damages FastMoving enemies (BarricadeDamage.cs:39-71); tar traps slow every in-range enemy (up to 64, picked in random order) for `recheckTargetInterval` and re-apply at that interval, with no Day check (AutoAttackTarTrap.cs:14-35); `KillOnTouch` deals 1e13 to tagged objects inside its box (KillOnTouch.cs:13-26); `TieBreaker` (only if present in the scene): once spawning is over, if for 30 s (`requiredTimeWithNoDeathsOrDestroyedBuildings`) neither the enemy count nor the alive-building count changes and no `Boss` exists, the first `EnemyOwned` takes 10 damage/s (`damagePerSecond`), no attacker (TieBreaker.cs:71-110).

**12. Additional effects (asset-attached).** HealOnKill (HealOnKillWeaponEffect.cs:15-25); flat/percent lifesteal (HealthStealWeaponEffect.cs:12; PercentageHealthStealWeaponEffect.cs:12); Execution: remaining HP dealt if target HP% <= threshold (def 15) (ExecutionWeaponEffect.cs:12-15); GodlyCurse: once per target per night `maxHp*pct` (UpgradeGodlyCurse.cs:25-32); Slow (SlowEffect.cs:12-15); radial Knockback (KnockbackEffect.cs:30-35; KnockbackBehavior.cs:100-132); Curse marks for CurseBlastMA (CurseEffect.cs:11); BloodWand active trades hero HP and slows the hero, passive stacks damage on one target (BloodWandActiveAttEffect.cs:15-27; BloodWandPassiveAttEffect.cs:18-33).

## (d) Targeting rules

Ranges live in `TargetPriority.range` (asset). `FindClosestTaggedObject` takes the globally nearest matching object and returns it only if within `range`; `minRange` is ignored there (TargetPriority.cs:26-39; TagManager.cs:279-297).

| Component | Rule | Cite |
|---|---|---|
| AutoAttack (default) | priorities in list order; first with an in-range match wins; nearest | AutoAttack.cs:123-135 |
| AutoAttackTower | mode enum: Closest (sorted, fills `simultaneousProjectiles`, spills to next priority), Random, HighestMaxHp, LowestHp incl. full HP, LowestHp excl. full HP (healing); array length caps targets | AutoAttackTower.cs:6-13,55-170 |
| WithMinRange | farthest in-range target, must be >= `minRange` (only the farthest is tested) | AutoAttackWithMinRange.cs:38-53; TargetPriority.cs:41-54 |
| HighestHealth / LowestHealth / Random | highest current HP; lowest HP% (skips full HP by default); random | AutoAttackHighestHealth.cs:5-17; AutoAttackLowestHealth.cs:5-19; AutoAttackRandom.cs:5-17; TargetPriority.cs:76-96,172-192,214-234 |
| TwoTargets / LowestInRangeMulti | 2 nearest; N (def 3) lowest HP% | AutoAttackTwoTargets.cs:29-40; AutoAttackLowestInRangeMulti.cs:54-65 |
| Player-unit adaptive | per `TargetPriorityExt`: nearest match, accepted only if within `range` and `attackDistance`; smallest distance wins; sets movement `keepDistanceOf=attackDistance-0.05`; optional secondary weapon | AutoAttackPlayerUnitAdaptiveWeapons.cs:44-83 |
| WithWarning | first cycle only marks; next cycle hits the marked target; mark cleared if it is not `AUTO_Alive` or beyond `breakTargetingDistance` (def 10) | AutoAttackWithWarning.cs:11,29-76 |
| Healer | attacks its `HealingTarget` within own `range` | AutoAttackHealer.cs:7-17 |
| Hero ManualAttack | locked target if within `priority[0].range`, else nearest by priority order; StabMA = lowest HP% (full HP included); PotionVial = priority 0 lowest-HP% injured target (full HP skipped), later priorities nearest | ManualAttack.cs:284-299; StabMA.cs:76-91; PotionVialAutoCast.cs:3-18 |

- **Who attacks what**: no hard-coded faction rules; attacker lists (AutoAttack) and mover lists (Pathfind*) are tag lists, and mover lists of enemies additionally veto `AUTO_Commanded` (PathfindMovementEnemy.cs:136-139). Knocked-out targets are excluded only if a list requires `AUTO_Alive` or vetoes `AUTO_KnockedOutAndHealOnDawn` (Hp.cs:404-405).
- **Aggro**: damage from an attacker tagged `Player` makes that enemy chase the hero for `agroTimeWhenAttackedByPlayer` (def 5 s) unless the hero is knocked out (Hp.cs:372-375; PathfindMovementEnemy.cs:101-112,211-216). Non-Weapon area/DoT damage (explosions, burn ticks, barricades, riding, godly curse, tie-breaker) has no attacker, so no aggro; Weapon splash passes the attacker, so a hero splash hit does aggro (Weapon.cs:178-197).
- **Flying vs ground**: no code rule excludes either; separation comes from modifier tags. Code effects: impact prefab choice (AimbotProjectile.cs:200-206), spawn 5 units up on a flying constraint (Spawn.cs:124-138,277), flying units use another graph and 2-D attract distance (CommandUnits.cs:129,226,517), and 3-D ranges include altitude.
- Tower upgrades multiply cooldown/range/damage/projectile speed, add arrows (resizing the target array), can insert a priority or turn a tower into a healer (`PlayerOwned`+`AUTO_Alive`, no Buildings) (TowerUpgrade.cs:65-110).

## (e) Movement rules

**Player units** (PathfindMovementPlayerunit.cs, A* `Seeker` + `RVOController`):
- Path request every `recalculatePathInterval` (def 1 s, random phase) to the nearest navmesh point of the target; fallback to `backupMovementGraph` on error or endpoint drift >0.1 (PathfindMovementPlayerunit.cs:232-278,331-337).
- Target: following the player -> `homePosition`; not yet within 3 of home since last placement -> home; else the first movement-priority hit (nearest, within its `range` of the unit); none -> home (PathfindMovementPlayerunit.cs:280-329,366-369). Hold mode = within `range` AND within 7 of home; non-hold has no leash (PathfindMovementPlayerunit.cs:286-293; TargetPriority.cs:299-347).
- Stops when distance to target < `keepDistanceOf` (def 2) and not walking home; else `rvo.SetTarget(next, min(speed, dist/dt), 1.15*speed)` and the position is snapped to the navmesh every frame (PathfindMovementPlayerunit.cs:371-401). Immune to `Slow` and aggro (PathfindMovementPlayerunit.cs:175-177,350-352). Commander upgrade: x1.6 speed while commanded, HP/damage x1.2 while holding (CommandUnits.cs:35-41,583-587; PathfindMovementPlayerunit.cs:139-159).
- Healer walks to the nearest damaged ally (or any enemy) (PathfindMovementPlayerunitHealer.cs:26-71).

**Enemies** (PathfindMovementEnemy.cs): path every interval (x2 when not chasing the hero) with per-object stagger (PathfindMovementEnemy.cs:236-259); chasing rewrites the path end to the hero each frame (PathfindMovementEnemy.cs:249-257); `keepDistanceOf` stop (PathfindMovementEnemy.cs:278-282); slow = speed x`speedWhenSlowed` (def 0.33), duration decays `dt/slowDurationMulti`, Ice Magic scales both (PathfindMovementEnemy.cs:140-144,312-320); optional stuck detection: 3 s stuck -> 5 s escape walk (PathfindMovementEnemy.cs:325-340). Melee enemies whose wave-wide spawn counter is odd use `backupMovementGraph`, splitting a wave across two routes (PathfindMovementEnemy.cs:147-150; Spawn.cs:266). `PathfindMovementBoss` uses a fixed RVO priority and locks in place inside `keepDistanceOf` (PathfindMovementBoss.cs:8-18), but no extracted prefab carries it (Boss-tagged Eldermole and Corrupt King use `PathfindMovementEnemy`: balance_sheet.json). A move applies only if the navmesh snap shifted <2 (PathfindMovementEnemy.cs:341-344).

**Hero** (PlayerMovement.cs): CharacterController plus RVO obstacle, no navmesh (PlayerMovement.cs:179-182,246); Unity colliders block it. Speed def 14, sprint 23, dead 8 (C# defaults, Day values equal them); asset (levels/*.json `heroes[0].movement`, all 36 hero scenes): speed 14, `speedDuringDay` 18.2, sprint 23, `sprintSpeedDuringDay` 29.9, dead 6.0; sprint needs HP=100% or a perk; Slow x0.33; heavy armor (night) and war horse multiply (PlayerMovement.cs:14-22,177,216-234). Input zeroed when `PlayerFrozen` (PlayerMovement.cs:165-168). Below y=-10 (asset -30) -> teleport to start (PlayerMovement.cs:32,247-252). "Change Timescale" toggles 1x/2x (PlayerMovement.cs:99-113,154).

**Army commands** (CommandUnits.cs; Rewired actions "Command Units", "Command Units Toggle", "Smart Command Units", "Select All Army/Melee/Ranged/Heroes", "Select Group 1-3"):
1. Hold/toggle: every PlayerUnit within `attractRange` (asset 6.0) of the hero (2-D for flyers) is added; each gets `FollowPlayer`, tag `AUTO_Commanded` and, without Commander, its AutoAttacks disabled (CommandUnits.cs:218-231,554-594). Select-All variants add without range and need the hero alive (CommandUnits.cs:165-205). Holding (or toggling on) the command button for 1 s while not commanding and within 4 (<=4) of a barracks select collider commands that barracks' units; progress +1/s, -1.5/s when the button is released (UnitProductionSelector.cs:15,17,75-95; CommandUnits.cs:143-147,283-288).
2. Release -> `commanding`; followers' `HomePosition` = hero position every frame (CommandUnits.cs:232-235,260-269).
3. Press again (edge) or hero KO -> place: AutoAttacks re-enabled; homes set around the hero (integer division gives every unit start angle 0: a jittered blob; then up to `maxPositioningRepeats` rounds (def 5, asset 50) pushing each unit of every pair within `unitDistanceFromEachOther` (def 2, asset 2.5) 0.5 further apart); in Day they teleport (CommandUnits.cs:239-244,481-552).
4. Keep holding >`holdToHoldPositionTime` (def 1 s, asset 0.5 s) -> `HoldPosition` (CommandUnits.cs:245-253,461-471). "Smart" only affects units named like the first added (CommandUnits.cs:494,561).
5. If setting `ResetUnitFormationEveryMorning` is on, dawn resets homes and clears hold (PathfindMovementPlayerunit.cs:206-212; SettingsManager.cs:624).
- Respawn: at night an alive barracks revives the first knocked-out unit each `timeToRespawnAUnitDependingOnLevel[level]` s (timer runs x`unitRespawnSpeedMulti` faster) and teleports it to the barracks; God of Death disables it (UnitRespawnerForBuildings.cs:53,77-98,121-136).

## (f) Hero

## (h) Bot implications (legit play only)

1. **Phases**: Day = safe (player objects invulnerable, turrets idle, manual attack off: Hp.cs:515; AutoAttack.cs:89-92; ManualAttack.cs:205): build, harvest, place the army. Night = position the hero and let auto-fire work.
2. **Hero damage is automatic and cannot miss** (homing, no collision: AimbotProjectile.cs:118-144). The job is spacing: stay within `targetPriorities[0].range` of wanted targets and outside enemies' 3-D ranges; press "Interact" for the active weapon when `CooldownPercentage` hits 0 (ManualAttack.cs:87).
3. **Focus fire**: default is nearest-first inside the first non-empty priority (ManualAttack.cs:284-299). Use Lock Target (edge-triggered) on outranging ranged/siege units, healers, then low-HP% finishers; re-evaluate after each kill (auto re-lock reuses the Lock Target lookup, ManualAttack.cs:180-187). Shrine charging favors high base-HP kills near a shrine (Shrine.cs:176-178).
4. **Kiting**: each hero hit pulls that enemy for 5 s (def), refreshed per hit, re-pathing every 1 s plus a per-object stagger of up to 1 s (immediately on the first hit); melee enemies halt at `keepDistanceOf` (PathfindMovementEnemy.cs:101-112,130,242-246,278-282). Drag slow melee along a loop away from walls/towers; do not sprint when hurt (needs 100% HP: PlayerMovement.cs:177).
5. **Avoid being surrounded**: an enemy targets the hero only if he is the nearest match of the first movement priority with any in-range match, or was just hit by him (PathfindMovementEnemy.cs:211-227). Keep army/buildings as closer matches, disengage below a safe HP%; when KO'd, walk away at 6 u/s (asset; def 8) before the in-place auto-revive; the aggro chase ends at KO (PathfindMovementEnemy.cs:211).
6. **Army workflow**: hold Command Units near units, release, walk to the choke point, press again and keep holding >0.5 s (asset; def 1 s) to set Hold (leash 7 around home; put home inside tower coverage). Followers do not fire and are ignored by enemy movement targeting (enemy weapons may still hit them), so never fight in follow state (except Commander). Re-issue daily if the reset-formation setting is on (PathfindMovementPlayerunit.cs:206-212).
7. **Protect barracks**: units respawn only at night while their barracks is alive (UnitRespawnerForBuildings.cs:83-98). Kill enemies within 20 (asset; def 10) of shrines to charge them.
8. **Sensing (read-only)**: `TagManager.instance.PlayerUnits/EnemyUnits/Players`; per object `Hp.HpValue/maxHp/KnockedOut`, `AutoAttack.onCooldown`, `AutoRevive.TimeTillRevive`, `PathfindMovementPlayerunit.HoldPosition/HomePosition`, `CommandUnits.commanding`. Hazard: `DamagePlayerWhenEnteringRange` hurts on entering range while moving (more when sprinting) (DamagePlayerWhenEnteringRange.cs:67-93).
